# 12 — Cable management Step 4: suggestion rules (pure JavaScript module)

**Goal:** a pure, Node-testable module `outputs/Mechanical_Design_App/cable-suggest.js` that computes routing suggestions for the Review tab and applies the safe ones to the draft. Claude is building the UI against the API below **in parallel**, so keep the names and return shapes exactly as written. Decisions: [work/cable-management/Step4_Decisions.md](../cable-management/Step4_Decisions.md) (read all 12). Data shape: Step 3's `cabling` block ([Step3_Decisions.md](../cable-management/Step3_Decisions.md)) plus the Step 4 additions (task 11). Suggestions are advice only: they block nothing and never claim a real cable or guide fits.

**Module pattern:** copy `cable-routes.js` (IIFE, `root.LabRaxCableSuggest = api`, `module.exports = api` under Node). No DOM, no fetch, no `window`. Context: `ctx = {ports: LabRaxPorts, cables: LabRaxCables, library: [items], newId?: () => string}`. Use `ctx.cables` for `endAnchor`, `endFace`, `path`, `crowded`, `guideLoad`, `portInUse`, `upkeep`, `TYPE_STYLE`; use `ctx.ports.portsFor(rack, placement, item)` for port lists (each port has `id`, `label`, `type`, `key` = `allocation/port`). Do not change `cable-routes.js` or `cable-ports.js`.

**Shared helpers (internal):** `U = 44.45`; an end's slot = `slotAt` of its anchor as in `cable-routes.js` (`slots - floor(z/U)`, clamped); an endpoint end's slot = the slot of the cable's `route.exit` if it exists, else the other end's slot. A cable's *post* = the post of its route guides when they are all on one post; when it has no guides, the post Step 3's autoRoute would pick (front `F` only when both ends are port ends with face `'front'`, else rear `R`; left `L` when the mean X of the known port anchors is < 0, else `R`). Guide labels in text: `RR U03` style.

**API (exact names):**
- `RULES`: ordered object, rule id → plain label: `'power-post'`, `'missing-guide'`, `'one-exit'`, `'top-exit'`, `'keystone'`, `'service-loop'`, `'short-run'`, `'bend'`, `'crowded'`, `'one-ended'`, `'unused-ports'`.
- `BEND_FACTOR = {rj45: 4, other: 10}` (any type except rj45 uses `other`).
- `carries(rack, cable, ctx)` → `'power'|'data'`: `cable.carries` if set; else `iec`/`dc-barrel` → power; `usb-c` → power when either connected port's `label` or `id` matches `/power/i`; else data.
- `powerPost(rack)` → `settings.power_post` or `'RR'`; `dataPost(rack)` → the other rear post.
- `suggestions(rack, ctx, {includeIgnored = false} = {})` → array sorted by `RULES` order, then subject. Each item:
  `{id, rule, level: 'suggest'|'guidance'|'info', title, detail, involves: {cables: [ids], guides: [ids], ports: [port keys], exits: [ids]}, apply: null | {...}, applyLabel: string|null, sig, ignored: bool}`.
  `id = rule + ':' + subject` (subjects below). `ignored` is true when `settings.ignored_suggestions` has an entry with the same `id` **and** `sig`; ignored items are left out unless `includeIgnored`. `title` and `detail` are short plain sentences (no jargon); keep "UNKNOWN"/"guidance" wording where the decision says so.
- `applySuggestion(rack, suggestion, ctx)` → `{ok: bool, message: string}`. Mutates `rack.cabling` only, and only for the four apply kinds below; first re-checks that every referenced cable, guide and exit still exists (else `ok: false`, nothing changed). After applying, calls `ctx.cables.upkeep(rack, ctx)`. The result must still pass `cable_plan.validate` (at most one guide per post per slot, ids exist). Never touches anything outside `rack.cabling`.
- `ignore(rack, suggestion)`: add or replace `{id, sig}` in `settings.ignored_suggestions` (create `settings` if needed; keep at most 500, dropping the oldest). `unignore(rack, id)`: remove it; delete the key when the list is empty.
- `pruneIgnored(rack, ctx)`: drop entries whose id is not among the current suggestions (computed with `includeIgnored: true`) or whose sig no longer matches; delete the key when empty. Returns the number removed.
- `sig`: 8-hex FNV-1a 32-bit hash of `JSON.stringify` of the involved state: the involved cables' `from, to, type, carries, route, service_loop_m, unplug_often`, the involved guides' `post, slot`, the involved exits' `position, slot`, and the involved port keys. Same state → same sig; any change → a different sig.

**Rules (subject in brackets):**
1. `power-post` [cable id], level suggest: consider only cables whose route guides are on rear posts. Guides on both RL and RR → "crosses between the rear posts". Guides all on one rear post that isn't the post for `carries` → "power belongs on RR" style. Apply `{kind: 'move-post', cable, guides}` where `guides` = guides on the right post whose slot lies between the two ends' slots inclusive, ordered from → to; applying sets `route = {mode: 'manual', guides, exit: <kept>}`. If that list is empty, `apply: null` and the detail says to add a guide on that post first. `applyLabel: 'Move to RR'` style.
2. `missing-guide` [post:slot], suggest: support points = from-end slot (skip an end with no slot), the route guides' slots in order, to-end slot. For each consecutive pair more than 2 slots apart (`|a-b| > 2`), the suggested slot is `Math.round((a+b)/2)` on the cable's post. Skip when a guide already sits at that post and slot, and skip cables whose guides are on more than one post. Merge cables that share the same post:slot into one suggestion. Apply `{kind: 'add-guide', post, slot}`: push `{id: ctx.newId?.() || 'guide-' + 12 random hex, kind: 'labrax-cable-guide', post, slot}`; refuse if the spot is taken. `applyLabel: 'Add guide'`.
3. `one-exit` [`all`], suggest: cables with an endpoint end whose `route.exit` is set. If they use 2 or more distinct exits, the target is the most-used exit whose position isn't `top-rear` (ties: order in `cabling.exits`); if none of the used exits qualifies, the most-used exit. Apply `{kind: 'set-exit', cables: [those not on target], exit}`: each gets `route = {mode: 'manual', guides: <kept>, exit}`.
4. `top-exit` [exit id], suggest: each `top-rear` exit used by at least one cable ("keep the top fan panel clear"). Apply `set-exit` for its cables to the most-used non-top exit, else the first non-top exit in `cabling.exits`; `apply: null` when there is none.
5. `keystone` [cable id], suggest: `cable.unplug_often === true` and neither end is a port of type `keystone`. No apply.
6. `service-loop` [cable id], suggest: effective service loop (`cable.service_loop_m ?? settings.service_loop_m ?? 0.15`) is 0 and the cable has at least one port end. No apply.
7. `short-run` [cable id], suggest: both ends are port ends with anchors, `|za - zb| < U`, and the route has at least one guide. Apply `{kind: 'drop-guides', cable}`: `route = {mode: 'manual', guides: [], exit: <kept>}`.
8. `bend` [cable id], level guidance: for each interior point of `ctx.cables.path(rack, cable, ctx)` with turn angle θ > 0 (angle between the incoming and outgoing directions), available radius `r = t / tan(θ/2)` with `t` = half the shorter neighbouring segment. Flag when `r < factor × diameter` (factor from `BEND_FACTOR`, diameter `TYPE_STYLE[type].diameter_mm`). One suggestion per cable naming the number of tight turns and the tightest (rounded mm, "nominal sizes, guidance only"); `involves.guides` = guides at those points. No apply.
9. `crowded` [guide id], suggest: each id in `ctx.cables.crowded(rack)`; involves that guide and every cable routed through it; the detail repeats that capacity is UNKNOWN and the number is the user's setting. No apply.
10. `one-ended` [cable id], suggest: `from` or `to` is null. No apply.
11. `unused-ports` [allocation id], level info: per placement, ports with no cable (`portInUse`). Only when at least one is unused. Title like "Pi 4: 7 of 9 ports unused" (name = `placement.assembly?.name || item?.name || 'Equipment'`). `involves.ports` = the unused port keys. No apply.
